# Development Preferences

Consolidated from global config/instruction files across Claude Code, Gemini CLI, pi, amp, and
GitHub Copilot CLI. Generated by the `collect-dev-preferences` skill — source of truth for these
preferences; regenerated in full on each run (not appended to). Do not hand-edit sections that a
future run would overwrite without expecting to lose those edits.

## Version control

- Prefer `jj` (jujutsu) over `git` for all VCS operations; repos are colocated
  (`jj git init --colocate`) so both work, but `jj` is primary (copilot).
- Custom `jj` aliases (defined in `~/.config/jj/config.toml`): `jj pull`, `jj push`, `jj tug`,
  `jj pr` (opens a GitHub PR via `gh`), `jj open`, `jj retrunk`, `jj reheat` (copilot).
- Custom revset aliases: `mine()`, `stack()`/`stack(x)`, `open()`, `ready()`, `wip()`,
  `private()`, `closest_bookmark(@)` (copilot).
- SSH signing configured (`~/.ssh/id_ed25519.pub`); `jj` drops signatures on rewrite by default
  unless `sign-on-push = true`; `git.sign-on-push = true` is set, writing change-id headers
  (copilot).
- GitHub remote URL shorthands rewrite `https://github.com/` → SSH automatically via
  `~/.gitconfig` (copilot).
- For operations `jj` doesn't cover (e.g. `git lfs`, submodules), fall back to `git` but note the
  exception explicitly (copilot).
- Claude Code is explicitly permitted to run `jj diff` without prompting
  (`~/.claude/settings.local.json`).

## Tool-use order

- Prefer LSP tools over direct file-based tools whenever possible: symbol lookup/definitions/
  references/hover via `lsp`, not grep/glob; diagnostics via LSP hover/documentSymbol rather than
  running a build; renames via `lsp rename`, not grep-and-replace; call graphs via
  `incomingCalls`/`outgoingCalls`. Overall order: **LSP tools > glob > grep > bash** (copilot).
- Claude Code has the `gopls-lsp` and `typescript-lsp` plugins enabled globally, consistent with
  this LSP-first preference (`~/.claude/settings.json`).

## Workflow conventions

- Every project is tracked by a Jira ticket (`ZING-\d+`). At the start of a session, if the ticket
  ID isn't known, ask for it and treat it as the current Jira ID for that session (copilot).
- Bookmark/branch naming: the primary bookmark for a ticket is named after the Jira ID
  (`ZING-41337`); sub-task or plan-step bookmarks are prefixed with the current Jira ID
  (`ZING-41337-add-auth-middleware`) (copilot).

## Model / provider defaults

- pi: default provider `github-copilot`, default model `gpt-5-mini`, default thinking level
  `low`, theme `dark` (`~/.pi/agent/settings.json`).
- Claude Code: reasoning effort level set to `low`, theme `auto` (`~/.claude/settings.json`).
- Gemini CLI: auth via API key, checkpointing enabled, preview features on, vim mode on, theme
  `Default` (`~/.gemini/settings.json`).

## Editor

- Gemini CLI preferred editor: `neovim` (`~/.gemini/settings.json`).

## Conflicts / notes

- No explicit "preferred editor" or "default model" setting exists for Claude Code, amp, or
  Copilot CLI itself — only pi and Gemini CLI expose these. Not a contradiction, just partial
  coverage.
- No conflicting VCS or tool-order preferences were found between tools; only Copilot CLI's
  global instructions state them explicitly, and nothing in Claude Code/Gemini/pi contradicts
  them.
